## Evidence and priorities

A confirmed issue requires a valid input/event trace through a real entry point and an observable contract violation, with a deterministic regression where executable. Source-proven reachability is recorded separately from tested behavior. Hypotheses are not promoted by reviewer agreement. P1 means broken execution, corruption, nontermination or repeated side effects; P2 means recoverable incorrect state/output or lifecycle leaks; P3 means lower-impact inconsistencies. Severity follows actual consequences, not the mere presence of a race.

The inventory, transition tables, grouped issue records, module dispositions and review/check results below are maintained as implementation proceeds. The final model describes supported behavior, including explicit limitations, rather than implying arbitrary concurrent library calls are supported.

### Supported concurrency and retry boundaries

The parallel scheduler owns graph synchronization; workers have independent mutable execution resources and merge cache state under `cache_mutex`. Server execution admission owns run replacement; socket writers and client collection have their own locks; confirmation wait uses its condition mutex. Sequential executors/parsers/import resolvers/watchers are single-owner objects, not generally thread-safe shared objects. A retry may rerun successful external effects from an earlier failed recipe; Jake does not promise exactly-once external side effects. Cancellation cannot undo already completed shell effects.

### Import and upgrade failure boundaries

Import resolution mutates its target AST during merging. Failures before merge (for example, a missing import that is created before retry) clean up active-stack state and can be retried with the same resolver. Allocation failure after partial merge requires discarding/deinitializing the target rather than treating it as a rolled-back transaction. The sweep does not introduce a general transactional-merge guarantee.

Upgrade is a separate staged-file lifecycle: select release → download candidate → verify when available unless explicitly skipped → install replacement → release temporary storage. Live release downloads and replacing the developer's installed executable are excluded from validation. Local file tests exercise replacement/recovery logic; Windows replacement behavior simulated through the helper is distinguished from native Windows execution.

| Upgrade state | Event / guard | Next state / owned resources | Failure invariant |
| --- | --- | --- | --- |
| Installed | Chosen release requires upgrade | Downloading a unique candidate beside the installed binary | Existing installation stays intact; staging on the same filesystem permits rename-based installation. |
| Candidate downloaded | Verification enabled and checksum available | Verified candidate or checksum failure | Mismatch rejects candidate; verification can explicitly be skipped or unavailable, matching existing policy. |
| Ready to install, POSIX | Rename candidate over installed path | New installation | Rename failure leaves previous installation; temporary candidate is cleaned. |
| Ready to install, Windows | Rename installed file to backup, then candidate into installed path | New installation plus backup | If the second move fails, restore original path; if restore itself fails, retain backup for recovery. |
| Any pre-install failure | Abort / error | Previous installation plus no live candidate | Temporary candidate has one cleanup owner; an error must not erase the only recoverable executable. |

## Cache attempt and publication model

A certificate acknowledges one consumer artifact, not merely that another recipe saw the same input. The scope is a file recipe or a recipe plus directive index. The Cache module owns its serialized encoding. Legacy unscoped records cannot satisfy scoped consumers.

| From / event | Transition / invariant | Failure, retry and durability |
| --- | --- | --- |
| Absent, changed or unavailable fingerprint | Consumer is stale; an empty glob is unavailable, never fresh. | Hash.mtime=-1 marks unavailable; scoped usable signatures use 0. Timestamps never bypass content comparison. |
| Real recipe admitted, before mutable work | Remove old persisted cache; invalidate prior in-memory consumer certificate. | A failed removal aborts before commands. Failure/interrupt cannot revive the removed on-disk certificate on the next CLI invocation. |
| Protected work about to read inputs | Capture content and glob membership; keep pending fingerprints owned by this recipe. File-target capture follows pre-hooks. | Allocation failure aborts; failed work cannot retain its prior usable certificate. |
| Body, later command or post-hook cancellation fails | Discard pending records; keep unavailable state and merge its invalidation delta. | Retrying must execute again; already completed external effects can repeat. |
| Complete recipe succeeds past cancellation fence | Publish captured signatures, rather than re-reading after work; finish fallible executed bookkeeping before terminal success. | One started task receives one terminal event; cache persistence is not an exactly-once execution acknowledgement. |
| Worker takes snapshot / returns | Cache.fork clears dirty bits; worker→graph→runtime merges only dirty entries under cache_mutex. | Untouched old records cannot overwrite sibling publications. Hash.dirty and tracks_changes are runtime metadata, not serialized. |
| Dry-run | Render commands without staging, retiring or publishing certificates. | A later real run still builds changed inputs. |

These are declared-input semantics, not hermetic filesystem snapshots. Transient/ABA rewrites, undeclared inputs and external output mutation are not isolated. Cache persistence/merge is best-effort; crash or OOM can cause conservative extra rebuilding. Multiple independent Jake processes sharing a cache are not coordinated or verified; there is no inter-process lock. Concurrent worker allocation requires a thread-safe allocator. Content checking adds I/O; no performance improvement is claimed.

The threaded scheduler table describes worker mode. Serial/dry-run uses topological execution without updating every private node terminal state; both reset eligibility before another attempt. Ordinary post-hook errors warn and preserve the body result; cancellation overrides success. Pre-hook failures abort; on-error hook failures do not replace the original failure.

### Before / after caller examples

The scoped-cache methods were introduced during Sweep A of this same unpublished branch; changing them to typed Scope does not break the baseline public Cache API. Baseline raw file APIs and allocator ownership inputs are preserved. Legacy unscoped records rebuild conservatively.

- Cache block: allocate and free a recipe-plus-separator-plus-index string → pass Scope{ .block = .{ .recipe = name, .index = i } }; Cache alone serializes/matches it.
- Parallel: construct with Context, then assign dry_run and verbose again → construct once; standalone public overrides still apply to worker contexts.
- File dependency: each executor scans all recipes for matching output → index.getRecipeByOutput(path), preserving source-order first match.
- Watch fallback: copy a hand-maintained list of Context fields → copy Context, set watch_mode=true. New callbacks no longer disappear silently.
- CLI formatting: formatter writes, main writes again → formatter writes once; main reports the result.
- CLI output: main.getStdout forwards to compat.getStdOut → call compat.getStdOut directly.

Known boundaries: no native Windows/live self-upgrade, no TSan, no inter-process cache isolation, no exhaustive network backpressure or fuzz campaign. Import partial-merge OOM requires discarding the target AST rather than transactional retry. Legacy [Watcher.initWithIndex follow-up #38](https://github.com/HelgeSverre/jake/issues/38) exposes a non-fallible, shared mutable fallback Context; shipped CLI uses explicit contexts, and independent legacy library watchers remain a deferred ownership/API issue. Removing it requires an explicit compatibility decision for the non-fallible constructor and externally addressable ctx pointer. The deferred init -y flag and Tracy surface likewise need a public compatibility decision ([#39](https://github.com/HelgeSverre/jake/issues/39)); they are not silently removed based only on first-party callsites.
